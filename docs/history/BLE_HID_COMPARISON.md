## Changes from the earlier implementation

Added the previously omitted Protocol Mode characteristic. Replaced static HID
metadata responses with observable read handlers. Match the reference's read-only
versus write protection settings and Battery Read|Notify properties. Both input
reports now register SubscribedClientsChanged before advertising. All callback
registrations are retained and revoked when their owner drops.

Protocol/control writes validate a single 0/1 byte with zero offset. Protocol Mode
changes and Suspend/Exit Suspend are recorded; diagnostic input readiness is false
while suspended or in Boot Protocol. Neither this reference nor this port exposes
Boot Input Report characteristics; do not claim boot-protocol input support.
Malformed-write validation and fail-fast registration errors deliberately exceed
the reference's log-and-continue behavior.

The reference's BluetoothLEDevice.ConnectionStatusChanged tracking is represented
here by connected-LE/Classic DeviceWatcher events and GattSessionStatusChanged for
sessions observed on actual HID reads/writes/subscriptions. These are read-only
observations; they do not connect to or subscribe on behalf of the iPhone.
A bounded 64-event timeline records reads, writes, subscription callbacks and
connection/session events. Diagnostic failures do not fail attribute responses.

The sole mouse subscriber may be selected automatically, but selection does not
send a movement test. Bluetooth connection, mouse subscription and keyboard
subscription remain separate fields. Windows SubscribedClients is the authority
for report readiness; successful advertising or tests cannot make it ready.

## Appearance / GAP: important correction

The inspected reference DOES NOT configure HID Appearance. Its README and
DEVELOPMENT explicitly document that Windows owns GAP/Appearance and cannot
publish the requested Appearance through the public desktop advertisement API.
This is a shared platform limitation, not an omitted working reference feature.
Windows also reserves GAP, GATT and Device Information services. We do not attempt
to fabricate these services or a duplicate CCCD.

## Physical acceptance

The user confirmed that the previous build reached STARTED and the iPhone showed
Bluetooth Connected, but both HID subscriber counts were zero. That did NOT pass
HID acceptance. The updated GATT table requires a fresh pairing attempt; forget
the previous PHH235 pairing on the iPhone, then pair while this provider stays up.
Do not mark this milestone passed until an actual mouse report subscription is
observed. The event timeline will distinguish no HID reads, incomplete metadata
reads and reads without a subscription. No input test is sent automatically.
