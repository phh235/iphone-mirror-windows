## Reference comparison

Reference: [WinBleTouch Program.cs](https://github.com/sakx7/WinBleTouch/blob/d80d659af53188c45d3d2966f86ec35c0849287f/Program.cs),
MIT Copyright (c) 2026 Sak. The reference source was downloaded at this exact commit.

| Item | This diagnostic implementation |
| --- | --- |
| HID service | 0x1812, Windows GattServiceProvider |
| Report Map | Standalone 78-byte single-finger touchscreen, byte-for-byte reference match; Report ID 1 |
| Previous composite keyboard | Removed only from DirectTouch profile; relative mouse/keyboard profile unchanged |
| HID Information | 11 01 00 01, matching reference |
| Creation order | Information, Report Map, Control Point, Protocol Mode, digitizer input and Report Reference |
| Information / Map | Plain readable metadata with observable successful read responses |
| Control Point | WriteWithoutResponse; 0 suspends, 1 resumes |
| Protocol Mode | Read + WriteWithoutResponse, initially 1 (Report) |
| Input report | 0x2A4D, Read + Notify, encrypted read; initial 02 00 00 00 00 00 |
| Report Reference | 0x2908, encrypted read, value 01 01; report ID is not prepended to payload |
| CCCD | 0x2902 generated by Windows for Notify |
| DOWN / UP | 03 / 02 state, contact ID 0, little-endian absolute X/Y in 0..10000; 6 bytes |
| Battery | Independent 0x180F, 100% readable 0x2A19, nonconnectable/nondiscoverable advertisement |
| HID advertisement | Connectable and discoverable |
| Appearance / PnP | Windows-managed/reserved; neither implementation fabricates these services |
| Delivery checks | Require GattCommunicationStatus Success AND BytesSent == 6, matching reference's acceptance checks |

Deliberate differences: notifications target the selected active subscriber through
NotifyValueForSubscribedClientAsync, instead of broadcasting through NotifyValueAsync.
The APIs return GattClientNotificationResult, including status, byte count and protocol
error. iMirror retains bounded waits, validates protocol/control writes, and requires
fresh Report Map discovery after switching profiles. The battery read is served by
a callback instead of StaticValue. No .NET/Python server or loopback touch endpoint
is incorporated. These differences are recorded; a matching descriptor alone is
not hardware acceptance.

## Trace and gates

The explicit --direct-touch-one-click switch starts DirectTouch diagnostics. The
normal production toolbar stays unchanged. No report is sent on startup, discovery
or selection. Only one real preview-window mouse DOWN is allowed per diagnostic
process. Extra DOWN attempts and drag movements do not send new contacts.

Preview WM_LBUTTONDOWN is recorded before forwarding to the parent. The trace then
records the parent event, readiness result and all blockers, target, successful
Report Map read state, physical client coordinates, viewport/stream state, mapped
coordinates, normalized and integer HID X/Y, queue acceptance/cancellation, actual
DOWN bytes, active GATT session, notification start and result. UP has its own
mouse/queue/bytes/notification records. Focus-loss or cancellation releases are
identified. No automatic DOWN retry occurs after an ambiguous failure.

Advanced Diagnostics reads the shared bounded trace on the UI timer even while
the input worker waits for GATT. File I/O stays on the input worker. The trace is
included in the local diagnostic JSON and remains intact across profile changes.
Each diagnostic process also writes a separate timestamped
`direct-touch-click-<pid>-<timestamp>.json` beside the status file, with executable
path and build ID `direct-touch-one-click-20260911-01`. Advanced Diagnostics shows
that archive path. Restarting the test cannot overwrite the previous process's trace.
It is bounded at 128 events and preserves early evidence if later events overflow.

Notification completion is Windows API evidence, not proof of an over-the-air
capture or iOS touch interpretation. Physical response must be confirmed by the user.

## iPhone setup required by the pinned reference

- Settings > Accessibility > Zoom: **ON**.
- Zoom Region: **Full Screen Zoom**.
- Zoom Level: **1x** (no visible magnification).
- Zoom Controller > Show Controller: **OFF**.
- Bluetooth: ON on both systems; Windows adapter must support BLE peripheral mode.
- After the new digitizer is advertising, forget the old PC pairing on the phone
  and pair the advertised PC again; accept pairing prompts on both devices. This
  profile changes the Report Map and Report Reference, so a cached relative-mouse
  descriptor must not be used. Wait for an active digitizer subscriber and a fresh
  successful Report Map read before clicking.

AssistiveTouch is not a prerequisite listed by WinBleTouch. No Apple ID, signing,
Developer Mode, jailbreak, iPhone app, WDA or XCTest is used by this path. USB may
continue to carry video; the touch report itself travels over Bluetooth LE.

Configure the phone first. The next hardware action is exactly one center-screen
click after inspecting readiness on the new binary. Do not test drag or keyboard.
